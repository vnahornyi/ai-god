## What the iterations showed

- A separate public skill `figma-ui`, and later a personal skill wrapping `figma-inspect`, were both
  tried first. With a second Figma skill installed, Sonnet stopped loading `figma-inspect` on case 1
  (0/3, against 3/3 with the wrapper link removed). The whole set came to 13/36. That is why the
  personal source is a plain overlay file and not a skill.
- Putting the "who writes the styles" question in a separate section before the procedure made
  sessions stop before loading domain skills. It now goes with the scope question in step 1, after
  the domain skills load.
- Most remaining misses are a missing `frontend-craft`. The harness has no Figma access, and the
  sessions stop as `figma-inspect` says before they read code. This happens at `495d7a9` too.
- The same run found a grader bug: `grade.py` sees only the skill names in its fixed list, so a new
  skill missing from the list drops out of both key and run. A new skill must be added there. The
  match now ends on `(?![\w-])`, so a longer name such as `figma-inspect-extra` no longer counts as
  `figma-inspect`.
